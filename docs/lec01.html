TL;DR

  • Language models need a tokenizer to convert raw text (bytes) into integer sequences — the choice of tokenizer profoundly affects model efficiency.
    语言模型需要分词器将原始文本（字节）转换为整数序列——分词器的选择深刻影响模型效率。
  • There's a fundamental trade-off: vocabulary size (smaller = less sparse) vs compression ratio (higher = shorter sequences for Transformer).
    核心权衡：词表大小（越小越不稀疏）vs 压缩率（越高序列越短，Transformer 处理越快）。
  • BPE (Byte Pair Encoding) is the dominant tokenization method — it's data-driven, starts from bytes, and iteratively merges the most frequent adjacent pair.
    BPE（字节对编码）是主流分词方法——数据驱动，从字节开始，反复合并出现频率最高的相邻对。
  • Course philosophy: understanding via building. accuracy = efficiency × resources. Algorithms that scale are what matter.
    课程理念：通过构建来理解。准确率 = 效率 × 资源。能 scale 的算法才重要。

Key Concepts

Tokenization
Tokenizer — Converts between raw strings and integer sequences (tokens). Must implement encode(str→list[int]) and decode(list[int]→str) with lossless round-trip.
分词器：在原始字符串和整数序列之间转换。必须实现 encode 和 decode 且能完美还原。
Tokenization Trade-off — A spectrum from bytes (small vocab, long seq) to words (large vocab, short seq). BPE sits in the sweet spot: controllable vocab, ~4x compression, no OOV.
分词权衡：从字节（小词表、长序列）到单词（大词表、短序列）的光谱。BPE 处于最佳位置。
Compression Ratio — bytes / tokens. Higher is better: means shorter sequences for the Transformer. BPE achieves ~4x compression on English text.
压缩率 = 字节数 / token 数。越高越好，意味着 Transformer 处理的序列越短。BPE 在英文上约 4 倍压缩。
Vocabulary Size — GPT-2: 50,257 tokens. GPT-4/5 (o200k): 200,019 tokens. Larger vocab = higher compression but sparser embeddings.
词表大小——GPT-2: 5 万，GPT-4/5: 20 万。词表越大压缩越好，但 embedding 更稀疏。
BPE Training — Start with bytes (vocab=256). Repeat: count adjacent pairs → merge most frequent → add merged token to vocab. Each merge increases compression.
BPE 训练：从 256 个字节开始，反复统计相邻对频率→合并最高频对→加入词表。每次合并提升压缩率。
BPE Encoding — Given a string, convert to bytes, then apply learned merge rules in training order. Greedy left-to-right, rank-based resolution for overlaps.
BPE 编码：将字符串转为字节，按训练时的顺序逐一应用合并规则。重叠时按 rank（学习顺序）贪心解决。
Pre-tokenization — Split text on word boundaries (regex) before BPE to prevent cross-word merges. GPT-2 uses a regex that isolates words, numbers, punctuation.
预分词：在 BPE 之前用正则按词边界切分，防止跨词合并。GPT-2 用正则分离单词、数字、标点。
Adaptive Computation — BPE implicitly makes the Transformer allocate more compute to rare/surprising tokens (more tokens per unit of meaning) and less to common patterns.
自适应计算：BPE 隐式地让 Transformer 对罕见/意外内容分配更多计算（每单位含义更多 token），对常见模式分配更少。
Transformer Architecture
Token + Position Embedding — Token ID → learnable vector ($d_{\text{model}}$ dims). Position embedding added element-wise so the model knows both "what I am" and "where I am."
Token + 位置嵌入：Token ID → 可学习向量。位置嵌入逐元素加上去，让模型同时知道「我是谁」和「我在哪」。
Self-Attention (Q/K/V) — Each token computes Query, Key, Value vectors. Attention score = softmax(QK⊤/√d). Allows every token to gather context from all other tokens in the sequence.
自注意力：每个 token 计算 Q、K、V 向量。注意力分数 = softmax(QK⊤/√d)。让序列中每个 token 从所有其他 token 收集上下文。
Causal Masking — For autoregressive LMs, token $i$ can only attend to positions $\leq i$. Enforced by setting future scores to $-\infty$ before softmax → lower-triangular attention pattern.
因果掩码：自回归语言模型中，token $i$ 只能关注位置 $\leq i$。通过将未来位置的分数设为 $-\infty$ 实现→下三角注意力模式。
Multi-Head Attention — Run $h$ independent attention heads in parallel, each with its own Q/K/V projections on $d_k = d_{\text{model}}/h$ dims. Different heads capture different relationship types.
多头注意力：并行运行 $h$ 个独立的注意力头，每个在 $d_k = d_{\text{model}}/h$ 维上操作。不同头捕获不同类型的关系。
Attention vs FFN — Attention = communication (tokens exchange info). FFN = computation (each token processes independently). These are the two core operations in every Transformer Block.
Attention vs FFN：Attention = 交流（token 之间交换信息）。FFN = 计算（每个 token 独立处理）。这是每个 Transformer Block 的两个核心操作。
Residual Connection — $x_{\text{new}} = x + f(x)$. Instead of replacing input, new information is added to it. Enables deep networks by letting gradients flow and building representations incrementally.
残差连接：$x_{\text{new}} = x + f(x)$。不替换输入，而是将新信息叠加上去。让梯度顺畅传播，逐层构建表示。
Normalization — Keeps value scales stable across layers. Modern LLMs use RMSNorm (simpler than LayerNorm). Applied before attention and before FFN (pre-norm).
归一化：保持数值在各层间稳定。现代 LLM 用 RMSNorm（比 LayerNorm 简单）。在 attention 和 FFN 前应用（前归一化）。
Logits & Softmax — Final linear layer maps $d_{\text{model}}$ → vocab size, producing logits (raw scores). Softmax converts logits to probabilities summing to 1.
Logits 和 Softmax：最终线性层从 $d_{\text{model}}$ 映射到词表大小，产生 logits（原始分数）。Softmax 将 logits 转为总和为 1 的概率。
Autoregressive Generation — Predict one token at a time, append it, repeat. The full sequence is re-fed each step. This is how ChatGPT produces text.
自回归生成：每次预测一个 token，追加到序列中，重复。每步都重新输入完整序列。ChatGPT 就是这样生成文本的。
Tensor Shape (B, T, D) — (batch_size, seq_len, d_model) — the universal shape throughout the Transformer. Input and output of each block have the same shape; only the meaning of the numbers changes.
张量形状 (B, T, D)：(批大小, 序列长度, 模型维度)——贯穿 Transformer 的通用形状。每个 block 输入输出形状相同，只是数字的含义变了。
Dropout — Regularization: randomly zeroes out activations during training to prevent overfitting. Forces the model to not rely on any single neuron.
Dropout：正则化方法，训练时随机将部分激活值置零防止过拟合。迫使模型不过度依赖某几个固定神经元。
Systems & Scaling (Preview)
Arithmetic Intensity — FLOPs / bytes moved. Determines whether an operation is compute-bound (high intensity) or memory-bound (low intensity). Key to GPU performance analysis.
算术强度 = FLOPs / 搬运字节数。决定操作瓶颈是计算（高强度）还是显存带宽（低强度）。GPU 性能分析的关键。
Kernel Fusion — Combine multiple GPU operations into one kernel to avoid redundant HBM round-trips. FlashAttention is the canonical example — fused attention via tiling.
核融合：将多个 GPU 操作合并为一个核，避免冗余显存往返。FlashAttention 是经典例子——通过 tiling 融合注意力。
Prefill vs Decode — Prefill processes all prompt tokens in parallel (compute-bound). Decode generates one token at a time (memory-bound). Different bottlenecks require different optimizations.
预填充 vs 解码：预填充并行处理所有 prompt token（计算瓶颈）。解码逐 token 生成（显存带宽瓶颈）。不同瓶颈需要不同优化。
Speculative Decoding — Small draft model generates candidate tokens; large model scores them in parallel. Mathematically exact (no quality loss), speeds up decode phase.
投机解码：小型草稿模型生成候选 token，大模型并行打分。数学上精确（无质量损失），加速解码阶段。
Chinchilla Scaling — Given compute budget $C \approx 6ND$, compute-optimal allocation is $D \approx 20N$ (train tokens ≈ 20× model params). Caveat: doesn't account for inference cost.
Chinchilla 缩放：给定算力预算 $C \approx 6ND$，计算最优分配是 $D \approx 20N$（训练 token 数 ≈ 20 倍模型参数）。注意：未考虑推理成本。
KV Cache — Store past Key/Value pairs during autoregressive decoding to avoid recomputation. Trades memory for speed — essential for efficient inference.
KV 缓存：自回归解码时存储历史 Key/Value 对避免重复计算。用显存换速度——高效推理的必要手段。
Course Philosophy
The Bitter Lesson — Not "scale is all that matters" but "algorithms that scale are what matter." Efficiency is more important at larger scales.
苦涩的教训：不是「规模就是一切」，而是「能 scale 的算法才重要」。规模越大，效率越关键。
Three Types of Knowledge — Mechanics (how things work), Mindset (squeeze hardware), Intuitions (which decisions yield good accuracy). CS336 teaches the first two.
三类知识：机制（事物如何运作）、心态（榨干硬件）、直觉（哪些决策带来好效果）。CS336 教前两种。
Expressivity / Stability / Efficiency — Every design decision in LLMs balances these three. Expressivity (model complex dependencies), stability (keep norms in goldilocks zone), efficiency (runs fast on hardware).
表达力 / 稳定性 / 效率：LLM 的每个设计决策都在平衡这三者。表达力（建模复杂依赖）、稳定性（数值范围合理）、效率（硬件上跑得快）。

Training: How do you set the parameters of the model?

训练：如何设定模型的参数？模型架构定义了「能学什么」，训练则决定「怎么学」。以下每个组件都是关键的设计选择：

Loss function — Standard: predict the next token (cross-entropy). Newer: multi-token prediction (MTP) — predict multiple future tokens at once, providing a richer learning signal. Used by DeepSeek-V3.
损失函数——标准做法：预测下一个 token（交叉熵）。更新的做法：多 token 预测——同时预测多个未来 token，提供更丰富的学习信号。DeepSeek-V3 采用。

Optimizer — How gradients update weights. Adam (2014) tracks per-parameter moving averages of gradient and squared gradient. AdamW (2017) decouples weight decay from gradient updates — the standard for LLM training. Newer: SOAP and Muon (2024) explore second-order-like methods for faster convergence.
优化器——梯度如何更新权重。Adam（2014）维护每个参数的梯度均值和平方梯度均值的滑动平均。AdamW（2017）将权重衰减与梯度更新解耦——LLM 训练的标准选择。更新的 SOAP 和 Muon（2024）探索类二阶方法以加速收敛。

Initialization scale — Weights can't start at zero (symmetry breaking), nor too large/small (gradient explosion/vanishing). Xavier init (2010) scales weights by $1/\sqrt{d}$ to keep activations stable across layers. muP (maximal update parametrization, 2022) goes further: ensures hyperparameters (like learning rate) transfer across model scales — train a small model, use the same hyperparams for a large one.
初始化尺度——权重不能从零开始（对称性破缺），也不能太大/太小（梯度爆炸/消失）。Xavier 初始化（2010）按 $1/\sqrt{d}$ 缩放权重以保持激活值跨层稳定。muP（最大更新参数化，2022）更进一步：确保超参数（如学习率）能跨模型规模迁移——在小模型上训练，大模型直接用相同超参。

Learning rate schedule — Learning rate isn't constant during training. Cosine annealing (2016): starts high, smoothly decays following a cosine curve. WSD (warmup-stable-decay, 2024): linear warmup → constant → rapid decay — simpler and increasingly popular.
学习率调度——训练过程中学习率不是恒定的。余弦退火（2016）：从高开始，按余弦曲线平滑衰减。WSD（2024）：线性预热→恒定→快速衰减——更简单，越来越流行。

Regularization — Prevent overfitting. Dropout: randomly zero out activations during training. Weight decay: penalize large weights by shrinking them slightly each step (pushes model toward simpler solutions).
正则化——防止过拟合。Dropout：训练时随机将激活值置零。权重衰减：每步稍微缩小权重（推动模型走向更简单的解）。

Batch size — How many examples per gradient update. Too small = noisy gradients, slow convergence. Too large = diminishing returns (each additional sample adds less new information). The critical batch size (2018) marks the transition: below it, larger batches speed up training linearly; above it, the benefit saturates.
批大小——每次梯度更新用多少样本。太小→梯度噪声大、收敛慢。太大→边际收益递减（每个额外样本贡献的新信息越来越少）。临界批大小（2018）标志着转折点：低于它，增大批量能线性加速训练；高于它，收益饱和。

MoE-specific: load balancing — In Mixture of Experts models, a router sends tokens to different experts. If all tokens go to the same expert, the others waste compute. Load balancing losses (or aux-free routing) encourage even distribution across experts.
MoE 专用：负载均衡——在专家混合模型中，路由器将 token 分配给不同专家。如果所有 token 都去同一个专家，其他专家就浪费算力了。负载均衡损失（或无辅助损失路由）鼓励在专家间均匀分配。

Systems — Resource Accounting

The key insight of systems optimization: Moving data in memory is surprisingly expensive — often more expensive than the computation itself. The GPU can multiply numbers blazingly fast, but it spends most of its time waiting for data to arrive from memory. The entire systems story — from kernels to parallelism to inference — is about one thing: how to minimize data movement.
系统优化的核心洞察：在内存中搬运数据非常昂贵——通常比计算本身更昂贵。GPU 能飞速做乘法，但大部分时间都在等数据从显存送过来。从核函数到并行化到推理，整个系统的故事都围绕一件事：如何最小化数据搬运。

Before optimizing anything, you need to measure. Resource accounting answers: how much compute and memory does my model need?

在优化任何东西之前，你需要度量。资源核算回答：我的模型需要多少计算量和显存？

Compute (FLOPs) — A simple rule of thumb for training:

计算量（FLOPs）——训练的简单估算公式：

total_flops = 6 * N * D
# N = number of parameters, D = number of training tokens
# Example: 70B params × 1T tokens
total_flops = 6 * 70e9 * 1e12 = 4.2e23 FLOPs

Why 6? Forward pass ≈ $2ND$ FLOPs (each parameter does a multiply-add per token). Backward pass ≈ $4ND$ (roughly 2× forward). Total ≈ $6ND$.
为什么是 6？前向传播 ≈ $2ND$ FLOPs（每个参数对每个 token 做一次乘加）。反向传播 ≈ $4ND$（约为前向的 2 倍）。总计 ≈ $6ND$。

Memory — Model parameters must be moved from memory (HBM) to compute units (SMs). GPU memory holds:

显存——模型参数必须从显存（HBM）搬到计算单元（SM）。GPU 显存需要存放：

  • Parameters: $N$ params × bytes per param (e.g., 2 bytes for bf16)（参数：$N$ 个参数 × 每参数字节数）
  • Gradients: same size as parameters（梯度：与参数同样大小）
  • Optimizer states: AdamW stores 2 extra copies (momentum + variance) → $2N$ more（优化器状态：AdamW 额外存 2 份——动量+方差→多 $2N$）
  • Activations: intermediate values saved for backward pass, scales with batch size × seq len（激活值：为反向传播保存的中间值，随 batch size × 序列长度增长）

Roofline analysis — determines whether an operation is compute-bound or memory-bound:

Roofline 分析——判断操作的瓶颈是计算还是显存带宽：

Arithmetic intensity = FLOPs / bytes moved
If intensity > machine's compute-to-bandwidth ratio → compute-bound (good! GPU is fully utilized)
If intensity < ratio → memory-bound (GPU is waiting for data, compute units idle)
算术强度 = FLOPs / 搬运字节数。如果强度高于机器的计算带宽比→计算瓶颈（好！GPU 被充分利用）。如果低于→显存瓶颈（GPU 在等数据，计算单元闲置）。

Example: B200 GPU — 2.25 PFLOP/s (bf16), 8 TB/s HBM bandwidth. Crossover point: $2.25 \times 10^{15} / 8 \times 10^{12} \approx 281$ FLOPs/byte. Operations with arithmetic intensity above 281 are compute-bound; below are memory-bound.
B200 GPU：2.25 PFLOP/s bf16 算力，8 TB/s 显存带宽。临界点：约 281 FLOPs/字节。算术强度高于 281 的操作是计算瓶颈，低于的是显存瓶颈。

Benchmarking: Theory is important, but always verify with profiling tools like Nsight Systems to see what actually happens on the GPU.（理论很重要，但一定要用 Nsight Systems 等分析工具验证实际运行情况。）

Kernels — Making GPUs Go Fast

A kernel is a function that runs on the GPU. Understanding kernels is key to understanding GPU performance.

核函数是在 GPU 上运行的函数。理解核函数是理解 GPU 性能的关键。

The problem with standard PyTorch: each primitive operation (matmul, add, activation) launches a separate kernel. Between each kernel, intermediate results are written back to HBM and then read again — wasteful round-trips.

标准 PyTorch 的问题：每个基本操作（矩阵乘法、加法、激活函数）各自启动一个核。每个核之间，中间结果写回 HBM 然后又读出来——浪费的往返。

# Naive: 3 separate kernels, 3 HBM round-trips
# 朴素方式：3 个独立核，3 次 HBM 往返
read HBM → compute A → write HBM    # kernel 1
read HBM → compute B → write HBM    # kernel 2
read HBM → compute C → write HBM    # kernel 3

# Fused: 1 kernel, 1 HBM round-trip
# 融合方式：1 个核，1 次 HBM 往返
read HBM → compute A, B, C → write HBM    # single fused kernel

Core principle: organize computation to minimize data movement.

核心原则：组织计算以最小化数据搬运。

Fusion strategies:

融合策略：

  • Operator fusion: combine matmul + activation into one kernel (e.g., matmul + SwiGLU)（算子融合：将矩阵乘法+激活函数合并为一个核）
  • Tiling (FlashAttention): break the $n \times n$ attention matrix into small tiles that fit in SRAM, compute tile by tile without ever materializing the full matrix in HBM（分块——FlashAttention：把 $n \times n$ 注意力矩阵切成能放进 SRAM 的小块，逐块计算，从不在 HBM 中生成完整矩阵）

Advanced GPU concepts (covered in Lec 05–06):

高级 GPU 概念（Lec 05–06 详细讲解）：

  • Warp divergence: threads in a warp take different branches → serialized execution（warp 分歧：同一 warp 中的线程走不同分支→串行执行，浪费并行性）
  • Memory coalescing: adjacent threads should access adjacent memory addresses for efficient reads（内存合并访问：相邻线程应访问相邻内存地址以提高读取效率）
  • Bank conflicts: multiple threads accessing the same shared memory bank → serialized（Bank 冲突：多个线程同时访问同一共享内存 bank→串行化）
  • Occupancy: ratio of active warps to maximum possible — higher ≈ better latency hiding（占用率：活跃 warp 占最大可能的比例——越高越能隐藏延迟）

Kernel languages: CUDA (low-level, full control), Triton (Python-like, used in Assignment 2), CUTLASS (NVIDIA's template library), ThunderKittens (research framework).
核函数编写语言：CUDA（底层、完全控制）、Triton（类 Python，A2 使用）、CUTLASS（NVIDIA 模板库）、ThunderKittens（研究框架）。

Parallelism — Scaling to 1000s of GPUs

What if you have 1024 GPUs? Data movement between GPUs is even slower than within a GPU, but the same "minimize data movement" principle holds.

如果你有 1024 张 GPU 呢？GPU 之间的数据搬运比 GPU 内部更慢，但同样的「最小化数据搬运」原则依然适用。

DGX B200 node: 8 GPUs connected via NVSwitch, 2 CPUs, NVMe storage. GPUs within a node communicate fast (NVLink); between nodes is slower (network).
DGX B200 节点：8 张 GPU 通过 NVSwitch 互联，2 个 CPU，NVMe 存储。节点内 GPU 通信快（NVLink），节点间通信慢（网络）。

Collective operations — the building blocks of multi-GPU communication:

集体通信操作——多 GPU 通信的基础组件：

  • All-reduce: every GPU sends its data, all GPUs receive the sum — used for gradient synchronization in data parallelism（All-reduce：每个 GPU 发送数据，所有 GPU 收到总和——用于数据并行中的梯度同步）
  • All-gather: every GPU sends its shard, all GPUs receive the full tensor（All-gather：每个 GPU 发送自己的分片，所有 GPU 收到完整张量）
  • Reduce-scatter: reduce + scatter result across GPUs（Reduce-scatter：归约后将结果分散到各 GPU）

What to shard across GPUs: parameters, activations, gradients, optimizer states — each can be distributed independently.

在 GPU 间分片的内容：参数、激活值、梯度、优化器状态——每个都可以独立分布。

Inference — Generating Tokens

Goal: generate tokens given a prompt. This is needed not just for serving users, but also for RL training (generate rollouts), test-time compute (chain-of-thought), and evaluation.
目标：根据 prompt 生成 token。不仅用于服务用户，还用于 RL 训练（生成 rollout）、测试时计算（思维链）和模型评估。

Inference has two phases with fundamentally different characteristics:

推理有两个阶段，特性截然不同：

Prefill processes all prompt tokens at once; Decode generates tokens one by one, using KV-Cache to avoid recomputation.
预填充一次处理所有 prompt token；解码逐个生成 token，用 KV-Cache 避免重复计算。

Methods to speed up decoding:

加速解码的方法：

1. Use a cheaper model:

1. 用更便宜的模型：

  • Model pruning: remove less important weights/neurons（模型剪枝：移除不重要的权重/神经元）
  • Quantization: reduce precision (FP16 → INT8 → INT4) — fewer bytes to load per parameter（量化：降低精度——每个参数需要加载的字节数更少）
  • Distillation: train a smaller model to mimic the larger one（蒸馏：训练一个小模型来模仿大模型）

2. Speculative decoding (exact!):

2. 投机解码（精确！）：

Use a cheap "draft" model to quickly generate multiple candidate tokens. Then use the full model to score all candidates in parallel (like prefill — compute-bound, fast!). Accept tokens that the full model agrees with. This is mathematically exact — produces the same distribution as the full model, just faster.
用一个便宜的「草稿」模型快速生成多个候选 token。然后用完整模型并行打分所有候选（像预填充一样——计算瓶颈，快！）。接受完整模型同意的 token。这是数学上精确的——产生与完整模型完全相同的分布，只是更快。

3. 系统层面优化：

  • KV cache: store computed Key/Value pairs from previous tokens — avoids recomputing attention for the entire history at each step（KV 缓存：存储之前 token 计算过的 Key/Value 对——避免每步重新计算整个历史的注意力）
  • Fused kernels: same principle as training — minimize HBM round-trips（融合核函数：与训练相同的原则——减少 HBM 往返）
  • Continuous batching: dynamically add/remove requests from a batch as they finish, maximizing GPU utilization（连续批处理：请求完成后动态添加/移除，最大化 GPU 利用率）

Inference optimization is increasingly critical because 4 use cases all require it: actual usage (serving), RL training (generate rollouts), test-time compute (reasoning chains), evaluation (benchmarks).

推理优化越来越关键，因为4 种场景都需要它：实际使用（服务）、RL 训练（生成 rollout）、测试时计算（推理链）、评估（基准测试）。

Scaling Laws Preview

Core problem: hyperparameter tuning at full scale is prohibitively expensive. Solution: scaling recipes with predictability.

  2. Fit scaling laws to predict larger scales（拟合缩放定律来预测更大规模）
  3. Extrapolate optimal recipe for target scale（为目标规模外推最优配方）
  4. Predict loss before running the expensive experiment（在运行昂贵实验之前预测损失）

Chinchilla 缩放：给定算力预算 $C \approx 6ND$，如何分配模型大小 $N$ 和训练 token 数 $D$？计算最优：$D \approx 20N$。例：70B 模型训练约 1.4T token。

ISOFLOP 曲线：对多个 FLOPs 预算分别找最优 $N$，然后拟合缩放定律外推到更大预算。

Key insight: Predictability is at least as important as optimality — we need preregistered predictions to validate our scaling laws.

关键洞察：可预测性至少和最优性一样重要——我们需要「预注册预测」来验证缩放定律。

Tokenization

The Problem

A language model operates on sequences of integers (tokens), but raw input is a Unicode string (bytes). We need encode(str → list[int]) and decode(list[int] → str) that round-trip correctly.

语言模型的输入是整数序列（tokens），但原始输入是 Unicode 字符串。需要 encode（文本→整数）和 decode（整数→文本）两个方法，且必须能完美还原（round-trip）。

Character Tokenizer

Map each Unicode character to its code point via ord().

字符分词器：把每个 Unicode 字符映射为其编码点（code point）。

class CharacterTokenizer(Tokenizer):
    def encode(self, string):
        return list(map(ord, string))  # ord("a")=97, ord("🌍")=127757
    def decode(self, indices):
        return "".join(map(chr, indices))
  • Vocab size: ~150K Unicode characters — huge and sparse（词表约 15 万——巨大且稀疏）
  • Compression: ~1 byte/token — poor（压缩率约 1——很差）
  • Worst of both worlds: large vocabulary AND low compression（两头不讨好：词表大 + 压缩差）

Byte Tokenizer

Encode string as UTF-8 bytes. Each byte is a token (0-255).

字节分词器：将字符串编码为 UTF-8 字节，每个字节就是一个 token（取值 0-255）。

class ByteTokenizer(Tokenizer):
    def encode(self, string):
        return list(map(int, string.encode("utf-8")))
    def decode(self, indices):
        return bytes(indices).decode("utf-8")
  • Vocab size: 256 — nice and small（词表只有 256——非常小巧）
  • Compression: exactly 1.0 — terrible (sequences are too long for Transformer's quadratic attention)（压缩率恰好 1.0——太差了，序列太长，Transformer 的二次方注意力吃不消）
  • Multi-byte characters: "a" = 1 byte, "🌍" = 4 bytes, "你" = 3 bytes（多字节字符：英文字母 1 字节，emoji 4 字节，中文 3 字节）

Word Tokenizer

Split on whitespace/punctuation using regex like \w+|.

词分词器：用正则表达式按空格/标点切分。

  • Compression: good (each token is a whole word)（压缩率好——每个 token 是一个完整单词）
  • Vocab size: unbounded — depends on data（词表大小无上限——取决于数据）
  • Problems: rare words waste vocab slots, OOV (unseen words → UNK token), no fixed vocab size（问题：稀有词浪费词表位置，未见过的词变成 UNK，词表大小不可控）

Byte Pair Encoding (BPE) ★

Originally a data compression algorithm (Gage, 1994). Adapted to NLP by Sennrich et al. (2016), then used by GPT-2.

BPE 最初是数据压缩算法（1994），后被 Sennrich（2016）引入 NLP 用于机器翻译，GPT-2 正式采用。

Core idea: train the tokenizer on data to build a vocabulary tailored to the corpus. Common byte sequences → single tokens. Rare sequences → many tokens.

核心思想：在数据上训练分词器，构建针对语料库定制的词表。常见字节序列→单个 token，罕见序列→多个 token。这是一种自适应的压缩方法。

BPE Training Algorithm

BPE 训练算法：从字节开始，反复找出出现最频繁的相邻 token 对，将其合并为一个新 token。

def train_bpe(string, num_merges):
    indices = list(string.encode("utf-8"))  # 第1步：把文本转为字节列表
    merges = {}
    vocab = {x: bytes([x]) for x in range(256)}  # 初始词表：256个字节

    for i in range(num_merges):
        counts = count_adjacent_pairs(indices)  # 第2步：统计所有相邻对的出现次数
        pair = max(counts, key=counts.get)       # 第3步：找到出现最多的相邻对
        new_index = 256 + i                      # 第4步：分配新的 token ID
        merges[pair] = new_index
        vocab[new_index] = vocab[pair[0]] + vocab[pair[1]]
        indices = merge(indices, pair, new_index) # 第5步：把所有该对替换为新token

    return BPETokenizerParams(vocab=vocab, merges=merges)

BPE Encoding

BPE 编码：拿到训练好的合并规则后，对新文本进行分词。按训练时的顺序逐一尝试每个 merge rule。

class BPETokenizer(Tokenizer):
    def encode(self, string):
        indices = list(string.encode("utf-8"))      # 先转为字节
        for pair, new_index in self.params.merges.items():
            indices = merge(indices, pair, new_index) # 按顺序尝试每个合并
        return indices

    def decode(self, indices):
        return b"".join(self.params.vocab[i] for i in indices).decode("utf-8")

Note: this naive implementation loops over all merges for every string. Assignment 1 requires an efficient version.

注意：这是最朴素的实现，对每个字符串都遍历所有合并规则。Assignment 1 要求实现高效版本（用 hash map + 优先队列）。

The merge() Helper

merge() 辅助函数：扫描序列，把所有匹配的相邻对替换为新 token。

def merge(indices, pair, new_index):
    new_indices = []
    i = 0
    while i < len(indices):
        if i+1 < len(indices) and indices[i]==pair[0] and indices[i+1]==pair[1]:
            new_indices.append(new_index)
            i += 2  # 跳过被合并的两个元素
        else:
            new_indices.append(indices[i])
            i += 1
    return new_indices

Why Tokenization? The Trade-off Spectrum

Why Not Feed Raw Text?

A Transformer operates on sequences of vectors. It needs discrete integer IDs to index into an embedding table. Raw text (a sequence of Unicode characters / UTF-8 bytes) must first be converted into a bounded set of integers.

Transformer 的输入是向量序列，需要离散的整数 ID 来索引 embedding 表。原始文本（Unicode 字符 / UTF-8 字节序列）必须先转换为有限集合内的整数。

Why Not Word Tokens?

Natural languages have effectively infinite vocabularies — new words, typos, code, multilingual text. A word-level tokenizer either (a) has a huge sparse embedding table, or (b) maps unseen words to UNK, losing information forever.

自然语言的词汇量实质上是无限的——新词、拼写错误、代码、多语言文本。词级分词器要么 (a) embedding 表巨大且稀疏，要么 (b) 把没见过的词映射为 UNK，永久丢失信息。

Why Not Character / Byte Level?

Byte-level (vocab = 256) solves the OOV problem, but sequences become extremely long. Self-attention is $O(n^2)$ — doubling sequence length quadruples compute. A 1000-word document becomes ~5000 bytes vs ~1300 BPE tokens.

字节级（词表 = 256）解决了 OOV 问题，但序列变得极长。Self-attention 的复杂度是 $O(n^2)$——序列长度翻倍，计算量翻四倍。一篇 1000 词的文档大约 5000 字节 vs 1300 个 BPE token。

The Tokenization Spectrum

Tokenization is fundamentally a trade-off between vocabulary size and sequence length:

Tokenization 本质上是在词表大小和序列长度之间做权衡：

  Byte                    BPE                     Word
   ◄──────────────────────┼──────────────────────►

  Vocab: 256              ~50K-200K               Unbounded
  Seq:   Very long        Moderate                Short
  OOV:   None             None                    Yes
  Sparse: No              Balanced                Very sparse
  ───────────────────────────────────────────────────────
  ← smaller vocab, longer seq    larger vocab, shorter seq →

BPE sits in the sweet spot: controllable vocabulary size (typically 32K–200K), good compression (~4x on English), no OOV, and data-driven — it adapts to whatever corpus you train on.

BPE 处于最佳位置：可控的词表大小（通常 32K–200K），良好的压缩率（英文约 4 倍），无 OOV，且是数据驱动的——会自适应训练语料。

Key insight: Tokenization is NOT just "how to split text." It determines the computational granularity of the Transformer — what the model "sees" as its atomic units, and how much compute it spends per unit of meaning.
核心洞察：Tokenization 不仅仅是「怎么切分文本」。它决定了 Transformer 的计算粒度——模型将什么视为原子单位，以及每单位意义消耗多少计算量。

What Does BPE Optimize?

BPE's Implicit Objective

BPE doesn't have an explicit loss function, but it implicitly optimizes a clear objective:

BPE 没有显式的损失函数，但它隐式地优化一个清晰的目标：

Maximize compression ratio (= bytes / tokens) subject to a fixed vocabulary budget.
最大化压缩率（= 字节数 / token 数），在固定词表预算下。

At each step, BPE greedily merges the most frequent adjacent pair — this is exactly the pair whose merge maximally reduces the total sequence length. It's a greedy compression algorithm.

每一步，BPE 贪心地合并出现频率最高的相邻对——这恰好是合并后能最大程度缩短总序列长度的对。它是一个贪心压缩算法。

Adaptive Computation

BPE creates an interesting property: the Transformer allocates computation adaptively based on token frequency.

BPE 创造了一个有趣的特性：Transformer 根据 token 频率自适应地分配计算量。

  • Common patterns (e.g., " the", " function") → single token → less compute per unit of meaning（常见模式→单个 token→每单位含义消耗更少计算）
  • Rare patterns (e.g., "xylophonist") → many tokens → more compute per unit of meaning（罕见模式→多个 token→每单位含义消耗更多计算）

This is actually desirable! Rare/unusual inputs are harder to predict, so they should get more model capacity. It's an implicit form of adaptive computation — the model automatically spends more "thinking" on surprising content.

这其实是好事！罕见/不寻常的输入更难预测，所以应该获得更多模型容量。这是一种隐式的自适应计算——模型自动在「令人意外的内容」上花更多「思考」。

The Tokenizer-Free Dream

The ultimate dream is architectures that operate directly on bytes without any tokenizer: ByT5, MegaByte, BLT (Byte Latent Transformer).

终极理想是直接在字节上操作的架构，完全不需要分词器：ByT5、MegaByte、BLT。

Why is this hard? Two requirements any solution must satisfy:

为什么这很难？任何方案都必须满足两个条件：

  1. Chunked processing: The model must operate on abstractions/chunks, not individual bytes — otherwise the $O(n^2)$ attention cost is prohibitive.（分块处理：模型必须在抽象/块上操作，而非逐字节——否则 $O(n^2)$ 的注意力代价太大。）
  2. Variable-length chunks: The chunks should be variable-length, allocating more capacity to "interesting" parts — exactly what BPE does implicitly.（变长分块：块应该是变长的，把更多容量分给「有趣」的部分——正是 BPE 隐式做的事情。）

Until byte-level models can match BPE-based models at frontier scale, BPE remains the practical choice.

在字节级模型能在前沿规模上匹配 BPE 模型之前，BPE 仍然是实际选择。

Attention Fundamentals

Tokenization produces a sequence of token IDs → embeddings. But how does the Transformer process this sequence? The answer is attention — the core mechanism that makes Transformers work.

Tokenization 产生 token ID 序列→嵌入向量。但 Transformer 如何处理这个序列？答案是注意力机制——Transformer 的核心运作机制。

Why Do We Need Attention?

Consider a simple approach: process each token independently through a feedforward network. The problem: no information flows between positions. The model can't understand context — it doesn't know what comes before or after each token.

考虑一个简单方案：每个 token 独立通过前馈网络。问题是：位置之间没有信息流动。模型无法理解上下文——它不知道每个 token 前后是什么。

We need a mechanism that lets each token look at other tokens to gather context. This is attention.

我们需要一种机制，让每个 token 能看到其他 token来收集上下文。这就是注意力。

Self-Attention Intuition

Self-attention answers the question: "For each token in the sequence, which other tokens should I pay attention to, and how much?"

自注意力回答的问题是：「对于序列中的每个 token，我应该关注哪些其他 token，关注多少？」

Example: In "The cat sat on the mat because it was tired", the token "it" needs to attend strongly to "cat" to resolve the pronoun.

例子：在 "The cat sat on the mat because it was tired" 中，token "it" 需要强烈关注 "cat" 来消解代词指代。

Query, Key, Value (Q, K, V)

Each token's embedding $x_i$ is projected into three vectors:

每个 token 的嵌入向量 $x_i$ 被投影为三个向量：

  • Query ($q_i$): "What am I looking for?" — represents the current token's information need（「我在找什么？」——代表当前 token 的信息需求）
  • Key ($k_j$): "What do I contain?" — represents what information each token offers（「我包含什么？」——代表每个 token 提供的信息）
  • Value ($v_j$): "What do I provide if selected?" — the actual content to aggregate（「如果被选中，我提供什么？」——实际要聚合的内容）

$q_i = W_Q x_i, \quad k_j = W_K x_j, \quad v_j = W_V x_j$

其中 $W_Q, W_K, W_V$ 是可学习的投影矩阵。

Attention Computation

The attention score between token $i$ (query) and token $j$ (key) is their dot product, scaled and softmaxed:

token $i$（query）和 token $j$（key）之间的注意力分数是它们的点积，经过缩放和 softmax：

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

Step by step:

逐步分解：

  1. Compute scores: $s_{ij} = q_i \cdot k_j$ — how relevant is token $j$ to token $i$?（计算分数：token $j$ 对 token $i$ 的相关度）
  2. Scale: divide by $\sqrt{d_k}$ to prevent softmax saturation with large $d_k$（缩放：除以 $\sqrt{d_k}$ 防止 softmax 在 $d_k$ 较大时饱和）
  3. Softmax: convert scores to probabilities (weights sum to 1)（Softmax：将分数转为概率，权重和为 1）
  4. Weighted sum: output $= \sum_j \alpha_{ij} v_j$ — aggregate values weighted by attention（加权求和：按注意力权重聚合 value 向量）

Causal (Autoregressive) Attention

For language modeling, we predict the next token. Token $i$ must only attend to tokens $\leq i$ (past and present), never to future tokens. This is enforced by masking: set $s_{ij} = -\infty$ for $j > i$ before softmax.

在语言建模中，我们预测下一个 token。Token $i$ 只能关注位置 $\leq i$（过去和当前），绝不能看到未来的 token。通过掩码实现：在 softmax 之前将 $j > i$ 的分数设为 $-\infty$。

$$\text{mask}_{ij} = \begin{cases} 0 & \text{if } j \leq i \\ -\infty & \text{if } j > i \end{cases}$$

This creates a lower-triangular attention pattern — each token only sees itself and its predecessors.

这产生了下三角注意力模式——每个 token 只能看到自己和前面的 token。

Multi-Head Attention

A single attention head can only capture one type of relationship. Multi-head attention runs $h$ independent attention heads in parallel, each with its own $W_Q, W_K, W_V$ projections, then concatenates the results:

单个注意力头只能捕获一种关系类型。多头注意力并行运行 $h$ 个独立的注意力头，每个有自己的 $W_Q, W_K, W_V$，然后拼接结果：

$$\text{MultiHead}(X) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) \, W_O$$

Each head operates on $d_k = d_{\text{model}} / h$ dimensions. Different heads can learn different relationship types: syntactic, semantic, positional, etc.

每个头在 $d_k = d_{\text{model}} / h$ 维上操作。不同的头可以学习不同类型的关系：句法、语义、位置等。

How Attention Connects to Tokenization

Tokenization and attention are deeply coupled:

Tokenization 和 attention 是深度耦合的：

  • Sequence length determines attention cost: Attention is $O(n^2)$. Fewer tokens (higher compression) = cheaper attention. This is the main reason we don't use byte-level tokenization.（序列长度决定注意力代价：注意力是 $O(n^2)$。token 越少（压缩率越高）= 注意力越便宜。这是我们不用字节级分词的主要原因。）
  • Token granularity determines what attention can "see": If "New York" is one token, attention treats it as an atomic unit. If it's two tokens, the model must learn to compose them.（Token 粒度决定注意力能「看到」什么：如果 "New York" 是一个 token，注意力把它当作原子单位。如果是两个 token，模型必须学会组合它们。）
  • Context window is measured in tokens, not words: With BPE's ~4x compression, a 128K-token context window covers ~500K bytes of text. With byte-level, it would only cover 128K bytes.（上下文窗口以 token 计，不是字数：BPE 约 4 倍压缩下，128K token 窗口覆盖约 500K 字节文本。字节级只能覆盖 128K 字节。）
Think of it this way: tokenization defines the resolution at which the Transformer perceives text. BPE gives a variable-resolution view — high resolution (many tokens) for rare content, low resolution (few tokens) for common patterns. Attention then operates at this resolution to build understanding.
可以这样理解：tokenization 定义了 Transformer 感知文本的分辨率。BPE 提供了可变分辨率的视角——对罕见内容高分辨率（多 token），对常见模式低分辨率（少 token）。然后注意力在这个分辨率上运作来构建理解。

本节端到端地拆解 GPT 风格的 decoder-only Transformer。核心思路：

位置嵌入与 token embedding 逐元素相加，让模型同时知道「我是谁」和「我在哪」：

Stacked Transformer Blocks

The embeddings pass through $N$ identical Transformer Blocks (e.g., $N = 24$ for a medium model):

嵌入向量通过 $N$ 个相同的 Transformer Block（例如中等模型 $N = 24$）：

Each block refines the representation. Early on, "bank" is just the word "bank." After many layers, if the context is "I deposited money in the bank", the vector shifts toward "financial institution." If the context is "I sat by the river bank", it shifts toward "riverbank."

每层都在精炼表示。最初 "bank" 只是「bank 这个词」。经过很多层后，如果上下文是 "I deposited money in the bank"，向量会偏向「金融机构」；如果是 "I sat by the river bank"，会偏向「河岸」。

Shape stays the same throughout: (batch_size, seq_len, d_model) in = (batch_size, seq_len, d_model) out. The numbers change, but the structure doesn't. Same shape, richer meaning.
形状自始至终不变：输入 (batch_size, seq_len, d_model)，输出也是。数字变了，结构没变。形状不变，含义越来越丰富。

Norm — Why Normalize?

With dozens or hundreds of layers, values can grow or shrink uncontrollably. Normalization keeps the scale of numbers stable across layers. Modern LLMs typically use RMSNorm (simpler than LayerNorm).

几十甚至上百层网络，数值可能不受控地变大或变小。归一化让数值范围在各层间保持稳定。现代 LLM 通常用 RMSNorm（比 LayerNorm 更简单）。

Causal Multi-Head Self-Attention

Three concepts packed into one name:

一个名字包含三个概念：

Self-Attention — tokens in the same sequence look at each other to gather context:

自注意力——同一序列中的 token 互相查看以获取上下文：

"The cat sat on the mat"

Processing "sat" → attends to:
  "The"  — low attention
  "cat"  — HIGH attention (who sat?)
  "sat"  — some self-attention

Causal — each token can only see itself and past tokens, never the future (otherwise the model is cheating at next-token prediction):

        The  cat  sat  on   mat

Multi-Head — attention runs multiple times in parallel with different learned projections. Different heads can capture different relationships:

多头——注意力用不同的学习投影并行运行多次。不同的头可以捕获不同的关系：

  • Head 1 → syntactic (who is the subject?)（句法：谁是主语？）
  • Head 2 → semantic similarity（语义相似性）

  • Head 4 → long-range dependencies（长距离依赖）

Multi-Head Attention = looking at context from multiple perspectives simultaneously.（多头注意力 = 同时从多个视角审视上下文。）

Dropout

During training, randomly zeroes out some activations to prevent overfitting:

训练时随机将部分激活值置零，防止过拟合：

[0.2, 0.8, -0.5, 1.1]  → dropout →  [0.2, 0, -0.5, 0]

Forces the model to not rely on any single neuron.（迫使模型不过度依赖某几个固定的神经元。）

Residual Connection (Add)

The bypass arrows in the diagram represent residual connections. Instead of replacing the input, attention's output is added to the original:

图中的绕路箭头就是残差连接。不是丢掉原始输入，而是把 attention 的输出加到原始输入上：

$$x_1 = x + \text{Attention}(\text{Norm}(x))$$

Why add back? The model doesn't start from scratch each layer — it incrementally adds new information to existing representations:

为什么要加回来？模型不是每层推倒重来——而是在已有表示上逐步叠加新信息：

Layer 0: "bank" (just the word)
Layer 5: "bank" + money context
Layer 10: "bank" + financial meaning
Layer 20: "bank" + full sentence relationships

Residual connections also help gradients flow through very deep networks during training.（残差连接还帮助梯度在非常深的网络中传播。）

Feed-Forward Network (MLP)

After attention lets tokens communicate, the feed-forward network lets each token think independently. It's a simple MLP applied to each token position separately:

注意力让 token 之间交流后，前馈网络让每个 token 独立思考。它是一个简单的 MLP，分别应用于每个 token 位置：

d_model → d_ff → d_model
  4096  → 11008 → 4096     (expand, activate, project back)

Key distinction — worth memorizing:

关键区别——值得牢记：

Attention = communication (tokens talk to each other)
FFN = computation (each token processes independently)
Attention = 交流（token 之间互相交流）
FFN = 计算（每个 token 独立处理）

Why "position-wise"? Because each token position uses the same MLP independently — "The", "cat", and "sat" each go through FFN separately. Cross-token interaction only happens in Attention.（为什么叫 "position-wise"？因为每个 token 位置独立使用相同的 MLP。token 之间的交互只在 Attention 中发生。）

Complete Block — Two Lines of Math

The entire Transformer Block boils down to two equations:

整个 Transformer Block 可以浓缩为两个等式：

$$x_1 = x + \text{Attention}(\text{Norm}(x))$$ $$x_2 = x_1 + \text{FFN}(\text{Norm}(x_1))$$

That's it. Normalize → Attention → Add back → Normalize → FFN → Add back. Repeat $N$ times.

就这些。归一化 → 注意力 → 加回来 → 归一化 → FFN → 加回来。重复 $N$ 次。

Final Norm → Linear → Softmax

After all $N$ blocks, the final token's representation needs to become a probability distribution over the vocabulary:

经过所有 $N$ 个 block 后，最后一个 token 的表示需要变成词表上的概率分布：

  1. Final Norm — stabilize one last time（最终归一化——最后稳定一次数值）
  2. Linear layer — project from $d_{\text{model}}$ to vocabulary size, producing logits (raw scores, not probabilities):（线性层——从 $d_{\text{model}}$ 投影到词表大小，产生 logits（原始分数，还不是概率）：） 
    [0.4, 1.2, -0.3, 0.8]   →   Linear   →   [1.2, -0.4, 3.1, 0.7, 0.2]
     d_model=4                              vocab_size=5 (logits)

    logits:         cat=1.2  dog=-0.4  mat=3.1  sat=0.7  the=0.2
                         ↓ softmax
probabilities:  cat=0.10 dog=0.02  mat=0.70 sat=0.11 the=0.07
                                                     sum = 1.00

The model predicts: next token is most likely "mat" (70%).

Autoregressive Generation

Architecture Summary

Compress the entire architecture into one mental model:

把整个架构压缩成一个心智模型：

Raw text
   ↓
Tokenizer (BPE)
   ↓
Token IDs
   ↓
Token Embedding + Position Embedding
   ↓
┌─────────────────────────────────┐
│      Transformer Block  × N    │
│                                 │
│  Attention  — tokens communicate│
│  FFN / MLP  — tokens compute   │
│  Residual + Norm — stay stable  │
└─────────────────────────────────┘
   ↓
Final Norm
   ↓
Linear → vocab logits
   ↓
Softmax → next-token probabilities

5 core concepts to remember:

5 个核心概念：

  1. Embedding — token ID → learnable vector（把 token ID 变成可学习的向量）
  2. Position — tells the model where each token is（告诉模型每个 token 在哪个位置）
  3. Attention — lets tokens gather information from each other（让 token 之间交流信息）
  4. FFN / MLP — lets each token do its own computation（让每个 token 自己进一步计算）
  5. Softmax — turns model output into next-token probabilities（把模型输出转成下一个 token 的概率）
Transformer Block = Attention + Feed-Forward, with Norm and Residual Connections for training stability.
Transformer Block = Attention + Feed-Forward，加上 Norm 和残差连接保证训练稳定性。
