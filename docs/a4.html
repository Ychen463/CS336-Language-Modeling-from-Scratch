Key Concepts

Data Pipeline
Transformation — convert raw HTML/PDF to clean text, extract main content, strip boilerplate.
转换——将原始 HTML/PDF 转为干净文本，提取正文，去除模板。
Quality Filtering — train classifiers to identify high-quality text and remove low-quality / harmful content.
质量过滤——训练分类器识别高质量文本，移除低质量/有害内容。
MinHash Deduplication — use locality-sensitive hashing to efficiently find near-duplicate documents. Avoids wasting compute on repeated data and reduces memorization.
MinHash 去重——用局部敏感哈希高效发现近重复文档，避免浪费算力和减少记忆化。
Data Mixing — optimize the ratio of different sources (web, books, code, etc.) to improve downstream performance [Liu+ 2024] [Chen+ 2026].
数据混合——优化不同来源（网页、书籍、代码等）的配比以提升下游性能。
Alignment (Preview)
Weak Supervision — after pretraining with full supervision (next-token prediction), improve the model further using weaker signals. Key insight: it's easier to critique than to generate.
弱监督——预训练（下一个 token 预测）后，用较弱的信号进一步改进模型。关键洞见：评判比生成容易。
RLHF Template — (1) generate responses, (2) score with human/verifier/LM judge, (3) update model to prefer better responses.
RLHF 模板——(1) 生成回复，(2) 用人类/验证器/LM 评判打分，(3) 更新模型偏好更好的回复。

Notes

Core Deliverables

  • Convert Common Crawl HTML to text — extract main content, remove boilerplate（从 Common Crawl HTML 提取正文，去除模板内容）
  • Train classifiers to filter for quality and harmful content（训练分类器过滤质量和有害内容）
  • Deduplication using MinHash — efficiently find and remove near-duplicate documents（用 MinHash 高效发现和移除近重复文档）
  • Leaderboard: minimize perplexity given a fixed token budget（排行榜：在固定 token 预算下最小化困惑度）

Alignment Preview

Why Weak Supervision?

So far, we have trained a model on full supervision (predict the next token). Now that the model is reasonable, we can improve it further from weak supervision.（到目前为止我们用完全监督训练模型。现在模型已经不错了，可以用弱监督进一步改进。）

Why weak supervision? When it is easier to critique than to generate.
为什么用弱监督？因为评判比生成容易。

Basic Template

  1. Generate responses from the model（从模型生成回复）
  2. Score responses with a human, verifier, or LM judge（用人类、验证器或 LM 评判对回复打分）
  3. Update the model to prefer better responses（更新模型偏好更好的回复）

Algorithms

  • PPO (Proximal Policy Optimization) — classic RL algorithm for alignment [Schulman+ 2017] [Ouyang+ 2022]（近端策略优化——经典 RL 对齐算法）
  • DPO (Direct Preference Optimization) — for preference data, simpler than PPO [Rafailov+ 2023]（直接偏好优化——针对偏好数据，比 PPO 更简单）
  • GRPO (Group Relative Preference Optimization) — removes the value function entirely [Shao+ 2024]（分组相对偏好优化——完全去掉价值函数）

Challenges

  • RL algorithms are unstable and hard to tune（RL 算法不稳定且难以调优）
  • At scale, requires a lot of new infrastructure (inference with async rollouts)（大规模需要大量新基础设施——异步推理 rollout）
  • Constantly trading off systems efficiency and on-policyness（持续在系统效率和策略一致性之间权衡）
