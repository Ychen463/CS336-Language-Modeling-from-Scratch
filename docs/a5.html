Key Concepts

Alignment Algorithms
PPO (Proximal Policy Optimization) — classic RL algorithm; uses a value function to reduce variance. Standard RLHF approach [Schulman+ 2017] [Ouyang+ 2022].
近端策略优化——经典 RL 算法，用价值函数降低方差。标准 RLHF 方法。
DPO (Direct Preference Optimization) — reparameterizes the reward model into the policy, directly optimizing on preference pairs (chosen vs rejected). No separate reward model needed [Rafailov+ 2023].
直接偏好优化——将奖励模型重参数化到策略中，直接在偏好对上优化。无需单独的奖励模型。
GRPO (Group Relative Policy Optimization) — generates a group of responses, scores them, and uses group-relative advantages to update the policy. No value function needed [Shao+ 2024].
分组相对偏好优化——生成一组回复，打分，用组内相对优势更新策略。无需价值函数。
Tokenization (Review)
Tokenizer — converts strings ↔ tokens (integer indices). Must implement encode and decode with lossless round-trip.
分词器——在字符串和 token（整数索引）之间转换。encode 和 decode 必须无损往返。
BPE (Byte Pair Encoding) — data-driven heuristic: start from bytes, iteratively merge the most frequent adjacent pair. Controllable vocab size, ~4x compression.
字节对编码——数据驱动的启发式方法：从字节开始，迭代合并最高频相邻对。可控词表大小，约 4 倍压缩。

Tokenization Review

This section reviews key tokenization concepts covered in Lecture 01. Inspired by Andrej Karpathy's video on tokenization.（复习 Lecture 01 的分词概念。灵感来自 Andrej Karpathy 的分词视频。）

The Problem

Raw text is Unicode strings. A language model operates on sequences of integer tokens. We need encode(str → list[int]) and decode(list[int] → str).

原始文本是 Unicode 字符串。语言模型操作整数 token 序列。需要 encode 和 decode 两个方法。

Tokenizer Types

  • Character-based: list(map(ord, string)) — simple but long sequences, limited to Unicode code points（基于字符：简单但序列长，限于 Unicode 码位）
  • Byte-based: list(map(int, string.encode("utf-8"))) — fixed vocab of 256, but very long sequences（基于字节：固定 256 词表，但序列非常长）
  • Word-based: large vocab, OOV problems, morphologically blind（基于单词：词表大，有 OOV 问题，无法处理词形变化）
  • BPE: data-driven, starts from bytes, iteratively merges most frequent pair — the dominant approach（BPE：数据驱动，从字节开始，迭代合并最高频对——主流方法）

Key Implementation: merge()

def merge(indices, pair, new_index):
    """Replace all instances of `pair` with `new_index`."""
    new_indices, i = [], 0
    while i < len(indices):
        if i + 1 < len(indices) and indices[i] == pair[0] and indices[i+1] == pair[1]:
            new_indices.append(new_index)
            i += 2
        else:
            new_indices.append(indices[i])
            i += 1
    return new_indices

BPE Tokenizer Structure

@dataclass(frozen=True)
class BPETokenizerParams:
    vocab: dict[int, bytes]              # index → bytes
    merges: dict[tuple[int, int], int]   # (idx1, idx2) → new_idx

class BPETokenizer:
    def encode(self, string: str) -> list[int]:
        indices = list(map(int, string.encode("utf-8")))
        for pair, new_index in self.params.merges.items():
            indices = merge(indices, pair, new_index)
        return indices

    def decode(self, indices: list[int]) -> str:
        return b"".join(self.params.vocab[i] for i in indices).decode("utf-8")

Compression Ratio

compression_ratio = num_utf8_bytes / num_tokens. Higher is better — the Transformer sees shorter sequences.（压缩率 = UTF-8 字节数 / token 数。越高越好——Transformer 看到的序列越短。）

Summary

  • Character/byte/word tokenization are all highly suboptimal（字符/字节/单词分词都非常次优）
  • BPE is an effective data-driven heuristic（BPE 是一种有效的数据驱动启发式方法）
  • Chunks should be variable — allocate more model capacity to interesting/rare content（分块应该是可变的——对有趣/罕见内容分配更多模型容量）
  • Tokenization is a separate step; maybe one day do it end-to-end from bytes...（分词是独立步骤；也许有一天能从字节端到端处理……）
