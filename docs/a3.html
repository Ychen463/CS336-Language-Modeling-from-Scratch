TL;DR

  • Run training experiments at multiple scales, fit power-law scaling laws, extrapolate to larger compute budgets.
    在多个规模上运行训练实验，拟合幂律缩放定律，外推到更大算力预算。
  • Predict loss before running expensive experiments — the goal is predictability, not just optimality.
    在运行昂贵实验前预测损失——目标是可预测性，而非仅仅是最优性。
  • Leaderboard: minimize loss given a FLOPs budget.
    排行榜：在给定 FLOPs 预算下最小化损失。

Key Concepts

Scaling Laws
Scaling Recipe — a mapping from FLOPs budget → hyperparameters (model size, tokens, learning rate, etc.). Not a single run, but a recipe that generalizes across scales.
缩放配方——从 FLOPs 预算到超参数的映射。不是单次运行，而是可跨规模泛化的配方。
ISOFLOP Curves — for a fixed FLOPs budget, plot loss vs. model size to find the optimal $N$. Repeat for multiple budgets to find the scaling trend.
等 FLOPs 曲线——固定 FLOPs 预算，画损失 vs 模型大小图找最优 $N$。对多个预算重复。
Compute-Optimal Scaling — given $C = 6ND$ FLOPs, the optimal ratio is roughly $D \approx 20N$ (Chinchilla). E.g., 70B params → ~1.4T tokens.
计算最优缩放——给定 $C = 6ND$，最优比例约为 $D \approx 20N$。如 70B 参数 → 约 1.4T tokens。
Predictability over Optimality — the goal of scaling laws is not just finding the best config, but being able to predict loss before running expensive experiments.
可预测性比最优性更重要——缩放定律的目标不仅是找最佳配置，而是在运行昂贵实验前能预测损失。
Hyperparameter Transfer
µP (Maximal Update Parameterization) — parameterize the model so that optimal hyperparameters (e.g., learning rate) transfer across scales [Yang+ 2022].
最大更新参数化——让最优超参数（如学习率）在不同规模间可迁移。

Notes

Core Deliverables

  • Run training experiments at multiple scales (model size × tokens)（在多个规模上运行训练实验）
  • Fit power-law scaling laws to the gathered data points（对收集的数据点拟合幂律缩放定律）
  • Extrapolate optimal hyperparameters to larger compute budgets（将最优超参数外推到更大算力预算）
  • Predict loss before running the full-scale experiment (preregistered prediction)（在运行全尺度实验前预测损失——预注册预测）

Scaling Laws: The Big Picture

The Core Problem

Setting: if you had $10^{25}$ FLOPs of compute, what hyperparameters would you use to train a good model?（假设你有 $10^{25}$ FLOPs 的算力，你会用什么超参数来训练一个好模型？）

Too expensive to do hyperparameter tuning at full scale! The key insight is to think not of a single experiment, but of a scaling recipe: a mapping from FLOPs → hyperparameters.

在全规模上做超参数调优太昂贵了！关键见解是不要想单次实验，而是想一个缩放配方：从 FLOPs 到超参数的映射。

How to Build a Scaling Recipe

  1. Run experiments at various smaller scales (e.g., up to $10^{24}$ FLOPs)（在较小规模上运行实验，如 $10^{24}$ FLOPs 以内）
  2. Fit a scaling law to predict loss at the target scale (e.g., $10^{25}$ FLOPs)（拟合缩放定律来预测目标规模的损失）
  3. Optimize the scaling recipe targeting larger scale using small-scale experiments（用小规模实验优化针对大规模的缩放配方）
  4. Predict the loss before actually running the experiment (preregistered prediction)（在实际运行实验前预测损失——预注册预测）
Scaling laws don't happen automatically — they require careful construction of a scaling recipe. Parameterize the model in a way to get hyperparameter transfer [Yang+ 2022].
缩放定律不会自动出现——它们需要精心构建缩放配方。用能实现超参数迁移的方式参数化模型。
Predictability is at least as important as optimality!
可预测性至少和最优性一样重要！

Compute-Optimal Scaling (Chinchilla)

The N vs D Tradeoff

Given a FLOPs budget $C = 6ND$, should you use a bigger model ($N$) or train on more tokens ($D$)?

给定 FLOPs 预算 $C = 6ND$，应该用更大的模型（$N$）还是训练更多 token（$D$）？

ISOFLOP Method

Classic compute-optimal scaling laws [Kaplan+ 2020] [Hoffmann+ 2022]:

  1. ISOFLOP curves: for multiple small FLOPs budgets, sweep model sizes and find the optimal $N$ that minimizes loss（等 FLOPs 曲线：对多个较小 FLOPs 预算，扫描模型大小找到最小化损失的最优 $N$）
  2. Fit a scaling law to extrapolate optimal $N$ and $D$ to larger FLOPs budgets（拟合缩放定律将最优 $N$ 和 $D$ 外推到更大 FLOPs 预算）

Chinchilla ISOFLOP analysis: (Left) Loss vs parameters for fixed FLOPs budgets — each curve's minimum gives the compute-optimal model size. (Middle/Right) Optimal $N$ and $D$ scale as power laws with FLOPs. [Hoffmann+ 2022]

TL;DR: $D = 20N$ is roughly optimal. E.g., a 70B parameter model should be trained on ~1.4T tokens.

简言之：$D = 20N$ 大致最优。例如，70B 参数模型应在约 1.4T tokens 上训练。

Caveat: this doesn't take into account inference costs — in practice, you may want a smaller model trained on more tokens (overtrained), since inference is run many times.

注意：这没有考虑推理成本——实际中你可能想用更小的模型训练更多 token（过度训练），因为推理会运行很多次。

Live Example: Marin / Delphi

The Delphi Scaling Suite shows scaling law predictions in action across multiple FLOPs budgets (3e18 to 1e22). Key observations:

  • Each colored curve is a fixed FLOPs budget; the U-shape minimum traces the compute-optimal frontier (dashed gray line)（每条彩色曲线是一个固定 FLOPs 预算；U 形最小值连成计算最优前沿）
  • Forecasted points (×) are predicted before running the experiment — the ∆loss shows prediction accuracy（预测点 × 是在运行实验前预测的——∆loss 表示预测精度）
  • At 1e21 FLOPs: ∆loss = +0.011; at 1e22 FLOPs: ∆loss = +0.005 — remarkably accurate predictions（1e21 FLOPs 预测偏差仅 +0.011，1e22 FLOPs 仅 +0.005——非常准确）
